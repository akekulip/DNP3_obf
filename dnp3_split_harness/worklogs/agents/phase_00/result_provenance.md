# Phase 00 — Result / Report Provenance Audit

_Role: Reproducibility & Provenance Engineer. Scope: `dnp3_split_harness/reports/`._
_READ-ONLY audit. No experiments run, nothing regenerated. Generated 2026-07-15._

Goal: map every report back to (a) the script that produces it and (b) the
machine-readable raw data behind it; flag results that are **not** reproducible
from a documented command or that read as hand-authored / stale.

Method: `grep` of every output filename against the `.py` files (producer
confirmation), read of every markdown/HTML report, existence check of every
referenced raw artifact, and staleness check of script paths named in the
reports against the current (post-2026-07-06 two-harness split) tree.

Labels used in the table:
- **ANALYTIC** = derived purely from the six real-device PCAPs / a payload file
  (no live traffic issued).
- **LOOPBACK** = 127.0.0.1 dev smoke measurement.
- **RIG** = two-host Vision↔Hulk measurement.
- **NARRATIVE** = hand-authored prose/aggregate; numbers transcribed from other
  files, no producing script.

## Ranked provenance gaps (worst first)

1. **Hand-authored aggregate reports with zero direct producer** —
   `ack_delay_master_report.md`, `ack_timing_implementation_report.md`, and
   `dnp3_timing_obfuscation_briefing.html`. These are the most-cited, highest-
   visibility deliverables, yet every number is transcribed by hand from other
   files. The briefing HTML has **no machine-readable sibling whatsoever**. The
   individual figures are traceable to backed files, but the documents are not
   regenerable and could silently drift from their sources.

2. **`ack_separation_rig_results.md` — the headline scientific claim is not
   script-backed.** The 40 ms delayed-ACK separation threshold (the whole
   Phase-2A finding) comes from **manual `tshark` reading** of
   `acksep_refine.pcap`. The committed CSV (`ack_separation_client_matrix.csv`)
   records `pure_ack_emitted = undetermined-needs-privileged-capture`, so it does
   **not** substantiate the threshold table. No committed script reduces the
   pcaps to that table.

3. **June rig-replay reports reference deleted scripts AND a now-missing key
   artifact** — `ordered_replay_results.md`, `request_aware_replay_results.md`,
   `split_aggressiveness_sweep.md` (and `from_live_split_results.md`,
   `replay_results.md`, `split_results.md`, `baseline_segmentation.md`). All name
   pre-2026-07-06 paths (`replay_tools/…`, `pydnp3_harness/experiment_master.py`,
   `tcp_split_replay_server.py`, `captured_exchange.py`, `experiment_*.py`,
   `run_slave.py`) that no longer exist, so their "reproduce" commands are broken.
   Worse, the **800-measurement SOE claim** in the ordered / request-aware reports
   points to `logs/master/soe.csv`, and `logs/replay/` — **both now MISSING**.

4. **`rig_timing_matrix_results.md` — the rig aggregate has no in-repo producer.**
   `rig_timing/rig_matrix_results.json` and the two-host orchestration are made by
   an out-of-repo gambit SSH driver that is not committed. Only the per-config
   `*_timing_decisions.jsonl` (written by `split_server.py`) and the pcaps are
   repo-native. Not regenerable from this repository.

5. **`pad_rig_results.md` — headline number is an unbacked projection.** The
   size-padding *mechanism* is real (`run_outstation.py --pad-*`, per-type
   `DatabaseSizes` — confirmed), and three pcaps back the byte counts, but the
   attacker-impact figure (device-ID **0.90 → 0.797**) is explicitly a
   simulation/projection with **no raw file** behind it.

Minor: `tcp_ack_fingerprinting.md` cites a stale tool path
(`analysis_tools/analyze_tcp_ack_behavior.py`) though its CSVs are regenerable via
`analyze_ack.py`.

## The ~22,988-transaction claim — trace

- **Producer:** `characterize_ack_traces.py` (`build_transactions()`), which parses
  the six real-device DNP3-over-TCP captures with `tshark`, reconstructs one
  request→response transaction per payload-bearing DNP3 REQUEST, classifies each
  (combined vs separate ACK), and writes `reports/ack_trace_characterization.csv`
  — **22,988 rows** — plus `.json` and `ack_trace_summary.md`.
- **Raw source:** `../Traffic Trace/{AB1400,ION7550,SEL751}{,L}.pcap` (all six
  files present, dated 2026-06-10).
- **Where cited:** `ack_timing_implementation_report.md` (§0, §2 — "22,988 txns"),
  `ack_delay_master_report.md` (§2), and `WORKING_NOTES.md` ("csv 22988 rows").
- **Derived subset:** `attacker_eval.py` and `ack_fingerprint_eval.py` use the
  **11,494** device-specific rows (per-device: ION7550 4798, SEL751 4298,
  AB1400 2398) after excluding the shared reference outstation `10.0.0.2`.
- **Verdict:** SOLID provenance — regenerable by `python3 characterize_ack_traces.py`
  from committed PCAPs; the count flows into the ANALYTIC evaluations cleanly.
