# campaign_v1 figures

Generated by `_bin/make_figures.py` from `derived/transactions.csv` (63,360 transactions,
22 sessions), using the repository's own style module `defense4/timing/analysis/figstyle.py`
(vendored `utils_mpl` + `paper_palettes`, per the `ieee-paper-figures` conventions).

Each figure ships with a `.pdf` (manuscript), `.png` at 600 dpi (slides), `_data.csv` (the
numbers behind it), `.caption.md` (caption draft) and `.provenance.json` (input hashes,
statistical method, style record).

## Physical correctness

Rendered at final printed size and never rescaled in LaTeX: double-column figures are
515.52 pt = 7.16 in, single-column 252 pt = 3.5 in. Base type 9 pt Times New Roman, ticks and
legends 8 pt, all embedded as subset TrueType (`pdf.fonttype 42`), so text stays text.
Backgrounds are opaque white. Include with `\includegraphics{...}` at natural size.

## Encoding contract

One meaning per channel, and never colour alone:

| channel | meaning |
|---|---|
| colour (vermillion / blue) | arm: Timing OFF / Obfuscated |
| line style (solid / dashed) | arm, redundantly, for greyscale |
| marker (circle / square / triangle) | class: READ / SELECT / OPERATE |
| panel | class, wherever three panels fit |

The single exception is `fig_c04`, whose question *is* class separability: there the panels
are the arms and colour encodes class. Its caption states this.

## Legend placement

Every legend sits **outside the plot area**, in a reserved band above the panels, and the
panels of a multi-panel figure share one legend. A legend inside the axes can always land on
top of the data, and on a column-width IEEE figure there is rarely a genuinely empty corner,
so the placement is structural rather than tuned per figure (`_bin/figlegend.py`). Canvas
heights were increased when the band was reserved, so the panels keep their drawing area and
the printed widths are unchanged.

## In-figure text

The figures carry no explanatory text. Only legends, axis labels, tick labels, category
labels, panel identifiers (a)/(b)/(c) and panel titles appear; every number, method note and
interpretation lives in the caption. Reference lines are named in the legend rather than
annotated on the axes.

## Why the offset is what it is

The switch can only release a response it is already holding, so the scheduled release
`D = D_A + D_R` must exceed the outstation's own cross-layer response time. `D` is therefore
both the coverage knob and the latency the mechanism adds, which is what makes the choice a
trade-off rather than a free parameter. `D_R` alone sets what the observer sees, since the
master-visible CLRT equals `D_R`.

| D (ms) | native transactions coverable | added latency |
|---|---|---|
| 8 | 96.004 % | 8 ms |
| 16 | 99.669 % | 16 ms |
| **24 (chosen)** | **99.905 %** | **24 ms** |
| 28 | 99.965 % | 28 ms |
| 60 | 99.987 % | 60 ms |

The curve is already flat at 24 ms: going to 60 ms buys 0.082 further percentage points for two
and a half times the delay. The 0.095 % that arrive too late to be held is not a defect but the
coverage limit of the chosen operating point, and it predicts the residual measured under the
mechanism, 0.091 % of READ transactions departing from 4.000 ms by more than 1 ms. Native READ
CLRT reaches 83.5 ms, which is why the largest departure observed is 53 ms.

## Overhead

The mechanism trades latency for indistinguishability, and nothing else:

- **Latency.** Median end-to-end response time rises from 2.680 ms to 25.337 ms (READ),
  2.622 ms to 25.239 ms (SELECT) and 3.465 ms to 24.650 ms (OPERATE), i.e. about 21 to 23 ms
  added per transaction. The acknowledgment moves from about 0.55 ms to the configured anchor
  at 21.3 ms (read path) and 20.65 ms (control path). This delay is the mechanism, not waste.
- **Bandwidth: none, with the size carve disabled.** Every one of the 132 captures holds
  exactly 1,448 frames and 130,708 bytes on the wire for 440 transactions, in both arms, and all
  132 files are byte-identical at 153,900 bytes on disk. The timing mechanism adds no packet and
  no byte; it only moves packets in time. This holds because `shape_enable = 0` throughout this
  dataset. The same program with `shape_enable = 1` replicates one response into two
  master-facing frames with a second header set, so the no-overhead result belongs to the timing
  mechanism and not to the program as a whole.
- **Closed-loop rate.** A master that polls sequentially and waits for each response is bounded
  by the response time, so the achievable rate falls from roughly 370 to roughly 40
  transactions per second. Pipelined or parallel polling is not measured here.

## The residual, stated plainly

The read path and the control path are anchored differently, so under the timing mechanism the
acknowledgment arrives at about 21.3 ms for READ and SELECT but about 20.65 ms for OPERATE.
The cross-layer response time, the feature the paper targets, is driven to chance; an observer
who also measures the acknowledgment latency recovers a large part of the class signal. This is
visible as the vertical stratification in the `fig_c04` inset and as the second pair of bars in
`fig_c05`. It belongs in the limitations, not in a footnote.

## What these figures do not claim

No device identification (the classifier separates transaction *classes*, never device models).
No physical breaker operation time (the OPERATE interval is master-visible ACK-to-echo; the
control points used are isolated remote bits and no contact moved). No size, padding or
segmentation claim (`shape_enable=0` in both arms here). No relay-facing or exactly-once claim.
Per-transaction J is not recoverable from a master-facing capture, since the codebook draws J
per transaction; the J-independence these data support is that the master-visible interval stays
at 4.000 ms while J varies over {2, 6, 12} ms within every obfuscated block.

### Measured parameter behaviour (`sweep/sweep_points.csv`, 18 configuration points)

- **The observable follows `D_R` exactly.** At a fixed budget `D_A+D_R = 24` ms, the CLRT
  measured 1.999, 3.999, 8.001, 12.001, 16.000 and 20.001 ms for `D_R` = 2, 4, 8, 12, 16, 20,
  while the response time stayed within 25.31 to 25.33 ms. Cost is set by the budget, the
  visible feature by `D_R`, and the two are independent.
- **There is an upper bound.** Sweeping `D_A` at `D_R = 4` ms, the acknowledgment tracks `D_A`
  until it saturates at 31.07 ms and the CLRT stops being pinned (5.50 ms at `D_A = 32`,
  9.51 ms at `D_A = 36`, reproduced twice). The saturation matches the program's fail-open
  horizon `H = 30.8 ms`, the safety bound after which a held packet is released regardless. The
  horizon is counted from the arrival of the request, because the token burst that starves the
  queue is seeded there, so the usable region is `t(request to acknowledgment) + D_A + D_R < H`
  rather than `D_A + D_R < H`; that offset is why the measured saturation sits at 31.07 ms rather
  than at 30.8 ms. `H` follows from the fail-open pass budget of 18,000 units in the program, a
  reservoir depth of 64, and a measured loopback rate of 37.4 Mpps that is recorded in the control
  plane and is not enforced by the datapath. With the tail requirement of about 24 ms, the
  operating window is narrow and identified on both sides.
- **The chosen point is the tightest.** Release spread is smallest at `D_A = 20`, `D_R = 4`
  (CLRT standard deviation 0.007 ms), rising to 1.36 ms at `D = 8` and 1.53 ms at `D = 16`
  where the budget no longer covers the tail, and to 0.41 to 0.57 ms as `D_A` approaches `H`.

### Modes D1, D2 and D3 are not available in this binary

The architecture defines five modes (`OFF`, `D1_EVENT`, `D2_RESP`, `D3_ACK`, `D4_DUAL`), and the
control plane accepts and installs `mode = 1, 2, 3`. What confines the evaluated program to two
policies is narrower than "the other modes were removed": only `OFF` and `D4` have entries in the
disposition table that seeds the blocker reservoir, so no other mode arms a hold. Mode-conditioned
state handling for `D1`/`D3` and the `FAIL_OPEN` bypass predicate are still compiled in, and the
program's compiled-in default is `MODE_D3_ACK`. Configuring `D2` (`D_A = 0`) and `D3` (`D_R = 0`)
reads back correctly yet leaves the wire timing indistinguishable **in these measurements** from
`OFF`: CLRT 2.108 ms and 2.098 ms with the outstation's own acknowledgment at about 0.55 ms. They
are not structurally identical to `OFF`, since they still mark the transaction live and take one
loopback pass; the difference is below the resolution of these measurements. A measured comparison
of the four policies would need a different build, which this repository does not permit.

### The J parameter carries no master-visible cost

`J` schedules the relay-facing release at `T0 + J`. The value is drawn from the codebook on every
packet through the control block and latched for the OPERATE, so it varies per transaction and no
per-transaction `J` is recoverable from a master-facing capture. The master-visible OPERATE
interval stayed at 4.000 ms for every configured `J`. That independence is not a property of the
datapath: it holds because the control plane asserts `A > J_max + native acknowledgment` and
`R > J_max + native response` before it will arm. Any overhead attributable to `J` is relay-facing
and was not observed.
