## Open items

1. **mutation3 (inherited from m9, changed by m10).** `test_mutated_retry_form_never_claims[mutation3]` forges a
   0x0400 retry frame with `reserved` in 1..63 on RETURN_PORT. It passes on m8_02 and fails on m9 and m10. It is
   seen only with `CONTENTION_M6_SOURCES` pointing at the build; the default suite runs the generated m6.
   - m9: the value is cleared at snapshot and the frame reaches the master port (115 octets).
   - m10: the value survives the retry rows, N runs its loop passes (4 passes, nothing claimed), and T's parse_tev
     drops the frame (it accepts only `reserved == 0`).
   - RETURN_PORT is fed only by the switch's own recirculation, so the frame is not reachable from outside. The
     retry-form validation still has the gap m9 introduced; not fixed here.
2. **Kept limitation.** A master that sends a segment after its own RST: m10 restarts the RST once, and its stage-0
   pass refuses it on SEQ (`tests/test_reset_race.py::test_m10_open_limitation_a_master_sending_after_its_own_reset`).
3. **Two compilers.** The model suite tests the SDK 9.13.1 image; the switch loads the 9.13.2 image
   (`STEP4_PLAN_20261017.md`, residual risk).
