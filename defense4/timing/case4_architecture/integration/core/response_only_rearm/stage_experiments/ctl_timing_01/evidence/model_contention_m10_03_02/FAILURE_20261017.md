# model_contention on m10_03, attempt 02: 377/378 (`restart_SELECT_no_response_to_master`)

The restart ran (count_busy[5] +1) and the first RST was relayed once, but the held SELECT response reached the
master.

Cause: a dataplane defect, present since m6 and unchanged by m10 (`../m10_03/failure_analysis_20261017/README.md`).
- N cancels the connection at its stage-1 owner CAS. T learns of it only after N's stage-2 pass and the hand-off.
- The held response was released by its normal rule inside that window.
- The same window exists on m9_01 in the source interpreter: an RST 1–5 laps before a scheduled release lets the
  response reach the master (`tests/test_reset_race.py::test_known_defect_reset_propagation_window`).

OPEN: needs a contract decision (scope "never released after the reset reaches T", with the window stated, or require
a design fix). Not rerun, and not reclassified.

## Decision (Philip, 2026-10-17)

The contract is scoped to T's reset-application pass. This result stays a failure under the original contract and is
kept as recorded. Under the revised contract, the one release found came before T applied the reset (20.857867 against 20.880497),
and nothing was released afterwards. This run cannot verify the revised contract, though: its restart points did not
record T's release count, so `reset_application_check.py` reports `unattributed`. The propagation window is recorded
as a limitation, and the revised contract is verified only on runs that record the count.

RESOLVED: contract scoped by Philip; revised-contract check and evidence in m10_03/failure_analysis_20261017/README.md
