# Residency diagnostic build (plan step 3.1)

Instrumentation-only variant of the sbo_admission_01 composite (b8a35c6c6) that makes the held-original
recirculation observable by role. It changes no forwarding, timing or verdict logic; it only splits and adds
counters. Built to localize the 71,310 `OUT_HELD_REWAIT` on the first hardware milestone (10 READs + 1 SBO).

Do NOT treat this as a production build. The production sbo_admission_01 P4 and its build are untouched.

## What changed

Generated by `read/make_diag_t.py` -> `read/read_queue_timing_diag.p4` (a copy of the production T with only
these edits), composed by `build_diag.py` with the same ports as sbo_admission_01
(`port_map.HARDWARE_SHARED_PORT`: relay 9, N_ACK_RETURN 48, T_IN 180, HB_RETURN 181, HELD_RETURN 182).

- The `outcomes` register widens from `bit<4> x16` to `bit<5> x32` (and `outcome_count` 16 -> 32 entries).
  Register width is free on Tofino-1: same SALU, same stage.
- The three held-original re-wait counts are split. `keep_blocking` (blocker re-circulation), which counted
  nothing, now names a per-role lap outcome. All six use the existing single count()/outcome_count path, so
  no new register, no new table, and no new per-pass register access are added.

## Index -> role mapping (`outcomes` register, `p1.t_Ingress.outcomes`)

| index | role | site in read_queue_timing_diag.p4 |
|---|---|---|
| 0..13 | unchanged production outcomes | |
| 1 (`OUT_HELD_REWAIT`) | **OPERATE** held-original re-wait | `rewait_operate` (HB_RETURN qid 2) |
| 14 | **ACK** held-original re-wait | `rewait_ack` (HELD_RETURN qid 6) |
| 15 | **RESP** held-original re-wait | `rewait_response` (HELD_RETURN qid 4) |
| 16 | **ACK**-blocker lap | `keep_blocking(HELD_RETURN, 7, 16)` |
| 17 | **RESP**-blocker lap | `keep_blocking(HELD_RETURN, 5, 17)` |
| 18 | **OPERATE**-blocker lap | `keep_blocking(HB_RETURN, 3, 18)` |

OPERATE re-wait is kept on index 1 (the historical `OUT_HELD_REWAIT`) because that is the one re-wait count a
composite scenario asserts (`model_drive_composite.py`'s `T_released_the_OPERATE_once_after_holding` reads
`OUT_HELD_REWAIT` as the OPERATE-hold signal). Keeping OPERATE there holds default 70/70 at zero stage cost;
ACK and RESP move to the free indices 14/15.

`core/response_only/hw/snapshot_counters.py` reads these back into a `diag` block (per-role `rewait` and
`blocker_laps`); on the production build the register is 16 wide, so 14..18 read absent (reported as null).

|---|---|---|

| shared-port composite | same, `SHARED_PORT=1` | 57/57 |

The T-ON hold/release path (SELECT, OPERATE held-and-released, READ holds) is inside the default/shared
composite scenarios and passes. The "5ms SBO" (`evidence/milestone_sbo_01/ton5`) is a live-traffic silicon
run, not a model-driver scenario; the instrumentation is counting-only and cannot change its frames.

Note: the local model has no packet generator, so the blocker-lap counters (16/17/18) stay 0 in model runs;
they populate only on silicon (where the generator creates the circulating blocker tokens). The re-wait split
(1/14/15) is model-visible; model_default's pass of the OPERATE-hold assertion exercises the index-1 path.
