Joint size+timing bring-up on the RRC kernel (defense4_rrc_kernel), 2026-08-12 — the read_len=0 fix.

ROOT CAUSE (why the earlier configure-all --mode D4 disabled pktgen):
  frozen caseA config_params_d4 (defense4_caseA_setup.py:37) checks tbl_params.read_len == a.read_len
  (default 18). The RRC kernel RETIRED read_len (dead PHV -> reads back 0), so the check failed,
  chk.n_fail>0, and caseA line 612-616 defensively LEFT pktgen DISABLED. A cold switchd restart does
  NOT fix a dead binary field. The RRC wrapper forwards no --read-len, so it always used 18 -> always
  failed. This is control-plane only; NOT a kernel or frozen-caseA change.

FIX (control-plane only, no rebuild, no restart):
  Call the frozen caseA setup DIRECTLY with --read-len 0. Then config_params_d4 writes read_len=0 and
  checks == 0, which MATCHES the RRC kernel's dead-field readback -> no failure -> pktgen ARMS.
  read_len is unused by the RRC kernel (per-function exp_ack replaced it), so 0 is harmless.
