\section{Evaluation}
\label{sec:eval}

We answer the five objectives of Section~\ref{sec:threat} on a physical testbed. Each subsection
states the question, the method, the result, and what the result does not settle.

\subsection{Testbed and Dataset}
\label{sec:eval:testbed}

\textbf{Testbed.} A server running a DNP3 master reaches a physical SEL-751A feeder relay through
an Intel Tofino-1 switch running the program of Section~\ref{sec:impl}. The master has no other
path to the relay, which we confirmed by disabling the relay-facing port and observing that the
relay became unreachable. All timestamps are taken on the master-facing link, so every interval
reported here is one a passive observer on the control network could record.

\textbf{Arms.} \emph{Timing OFF} forwards the outstation's acknowledgment and response as they
arrive. \emph{Obfuscated} holds them and releases them on the deadlines of
Section~\ref{sec:design}. Both arms run the same loaded program with the size carve disabled, so
the only difference between them is the release schedule.

\textbf{Units.} We report per DNP3 \emph{exchange}: one request, the transport acknowledgment
that follows it, and the application response. A capture contains 480 exchanges. The same capture
contains 440 high-level operations if a SELECT and its OPERATE are counted as one
select-before-operate operation, and one TCP connection. We use exchanges throughout and never
mix the two conventions.

\textbf{Corpus.} The campaign is 22 grouped collection runs in one approximately five-hour
window, six captures per run, 132 captures in total. It contains 63{,}360 exchanges, 31{,}680 per
arm, of which 26{,}400 are READ, 2{,}640 SELECT and 2{,}640 OPERATE in each arm.

\textbf{Validation.} We re-derived every exchange from the raw captures with a reader independent
of the one used during collection, and reconciled it against the per-capture driver logs. All 132
captures agree: no retransmission, no malformed frame, no unpaired request, no out-of-order
timestamp, and a well-formed response to every request. Each capture holds 1{,}448 frames and
130{,}708 captured bytes. The captures are equal in size but not identical; all 132 hashes differ.

\subsection{RO4: Release Budget and Coverage}
\label{sec:eval:budget}

\begin{figure*}[tbp]
  \centering
  \includegraphics{figures/ndss/fig_budget_coverage}
  \caption{\textbf{Release budget and the coverage it buys.} (a) Fraction of Timing OFF exchanges
  whose interval exceeds a given value, per class, with the budget $D$ and the fail-open horizon
  $H$ marked. (b) Fraction of Timing OFF exchanges the switch cannot place on the schedule,
  against the release budget. Both ordinates are logarithmic and the full support is shown.}
  \label{fig:budget}
\end{figure*}

\textbf{Question.} What does the release budget $D = D_A + D_R$ buy, and what does it cost?

\textbf{Method.} The switch can release only a packet it already holds, so an exchange is
schedulable when the outstation answers within the budget measured from the anchor. We sweep the
budget against the measured Timing OFF distribution. $D$ is the coverage budget, not the delay
added to every exchange; the added latency is reported in Section~\ref{sec:eval:cost}.

\textbf{Result.} In Figure~\ref{fig:budget}, the budget of 24~ms covers 99.905\% of Timing OFF
exchanges, and 30 of 31{,}680 arrive too late to be held. Raising the budget has sharply
diminishing value: the curve is already flat at the operating point, and the fail-open horizon
of 30.8~ms bounds it from above, because a reservoir carrying a finite pass budget cannot starve
a queue indefinitely. The operating region is therefore narrow and closed on both sides.

\textbf{Interpretation.} A fixed budget buys coverage, not a guarantee. An exchange that arrives
after its scheduled release cannot be moved backwards in time, so a residual is structural rather
than a defect of the release logic.

\subsection{RO1: READ and SELECT Timing}
\label{sec:eval:ro1}

\begin{figure*}[tbp]
  \centering
  \includegraphics{figures/ndss/fig_interval_summary}
  \caption{\textbf{Measured interval per transaction class and arm}, over 22 grouped runs. Boxes
  span the quartiles and whiskers the full observed range, so the late-arrival tail is visible.
  The ordinate is logarithmic; sample sizes are given per panel.}
  \label{fig:intervals}
\end{figure*}

\begin{figure*}[tbp]
  \centering
  \includegraphics{figures/ndss/fig_ecdf_full_support}
  \caption{\textbf{Empirical distribution of the measured interval}, pooled over 22 grouped runs.
  The abscissa is logarithmic and spans the complete observed range; no observation is clipped.}
  \label{fig:ecdf}
\end{figure*}

\textbf{Question.} Does the read-path rule of~(\ref{eq:read}) replace the outstation's own CLRT
with the policy value?

\textbf{Result.} In Figure~\ref{fig:intervals}, the median CLRT under Timing OFF is 2.116~ms for
READ and 2.050~ms for SELECT, with interquartile ranges of 2.778~ms and 2.697~ms. Under the
mechanism both medians are 4.000~ms and the interquartile range of each falls to 0.006~ms, a
reduction of more than two orders of magnitude in spread. Figure~\ref{fig:ecdf} shows why the
median alone understates the change: the Timing OFF distributions rise in a small number of
discrete steps, so a single observation is informative about the class, whereas the obfuscated
distributions are a step at the scheduled release.

\textbf{Interpretation.} The release instant is computed from the outstation's acknowledgment and
a fixed offset, so it no longer depends on how long the device took. The concentration is not
total. A tail remains: the largest obfuscated READ interval is 57.182~ms, and 24 of 26{,}400 READ
exchanges depart from the scheduled release by more than 1~ms. These are exchanges whose response
reached the switch after its scheduled release, which is the coverage boundary of
Section~\ref{sec:eval:budget} seen from the other side.

\begin{figure}[tbp]
  \centering
  \includegraphics{figures/ndss/fig_within_campaign_stability}
  \caption{\textbf{Within-campaign stability across the 22 grouped runs}, in acquisition order.
  Markers are the run median and bars span the interquartile range. The runs come from one
  campaign and are not independent replications across days, devices, or deployments.}
  \label{fig:stability}
\end{figure}

\textbf{Stability within the campaign.} Figure~\ref{fig:stability} plots each grouped run in
acquisition order. The obfuscated median sits at the scheduled release in every run and for every
class, while the Timing OFF medians stay separated, so the effect is not an artefact of one run
or of drift over the five hours. These runs share a testbed, a device, and a session of the same
afternoon, so this is stability within the campaign and not evidence of generalisation.

\subsection{RO2: Master-Visible OPERATE Interval}
\label{sec:eval:ro2}

\textbf{Question.} Does the control-path rule of~(\ref{eq:control}) hold the master-visible
ACK-to-echo interval at the policy value while the relay-facing hold varies?

\textbf{Result.} The OPERATE median falls from 2.937~ms under Timing OFF to 4.000~ms under the
mechanism, with the interquartile range falling from 2.827~ms to 0.006~ms
(Figure~\ref{fig:intervals}). Under the configured hold codebook $J \in \{2, 6, 12\}$~ms, the
master-visible interval remained concentrated at the policy value across all 22 grouped runs.

\textbf{Interpretation and scope.} The implementation selects $J$ from the codebook per
transaction. The experiment observes only the master-facing outcome: the per-transaction draw,
the relay-facing release at $T_0 + J$, and any physical actuation are outside the measurement.
We therefore claim that the master-visible interval is insensitive to the configured codebook,
and not that a relay-facing hold was observed to vary.

\subsection{RO3: Transaction-Class Leakage}
\label{sec:eval:ro3}

\begin{figure*}[tbp]
  \centering
  \includegraphics{figures/ndss/fig_leakage_attackers}
  \caption{\textbf{Transaction-class leakage under the two attacker models}, leaving out one
  grouped run at a time over all 22 runs. (a) Balanced accuracy with grouped-run 95\% confidence
  intervals. (b) Mutual information in bits with jackknife intervals and the 99th percentile of a
  within-run permutation null. (c) to (e) Row-normalised confusion over all 22 held-out runs.}
  \label{fig:leakage}
\end{figure*}

\textbf{Question.} How much does the timing tell an observer about the transaction class, and does
that depend on whether the observer can retrain?

\textbf{Method.} We treat this as a three-class problem over READ, SELECT and OPERATE, for which
chance balanced accuracy is one third. Features are the two independent intervals, request to
acknowledgment and acknowledgment to response; the total response time is their sum and carries no
independent information, so it is excluded. Mutual information is estimated for the CLRT and
converted to bits, and is compared against a null built by shuffling class labels within each
grouped run over 1{,}000 permutations, which preserves the per-run class counts. Uncertainty is a
grouped-run jackknife. Every fold leaves out one grouped run.

\textbf{Result.} In Figure~\ref{fig:leakage}, the fixed adversary trained on Timing OFF traffic
reaches 0.651 balanced accuracy on held-out Timing OFF exchanges using the CLRT alone, and 0.733
using both intervals. Applied unchanged to obfuscated traffic it falls to 0.333 and 0.334, which
is chance. Mutual information between the CLRT and the class falls from 0.383~bits to 0.004~bits;
the Timing OFF value lies far above the permutation null, and the obfuscated value lies inside it.
The adaptive adversary, retrained on obfuscated traffic, remains at chance on the CLRT alone but
recovers to 0.651 when the acknowledgment latency is added.

\textbf{Interpretation.} The mechanism removes the cross-layer response time as a class feature,
which is the feature the reconnaissance literature uses, and against the adversary the threat
model describes this is decisive. It does not remove every timing feature. The read and control
paths are anchored differently, so their acknowledgment latencies differ, and an adversary willing
to collect obfuscated traffic and retrain can exploit that difference. The confusion panels show its
shape: OPERATE becomes separable while READ and SELECT stay confused with each other. Closing this
residual requires the two paths to share an anchor, which we have not implemented.

\subsection{RO4: Cost and Master-Facing Overhead}
\label{sec:eval:cost}

\begin{figure}[tbp]
  \centering
  \includegraphics{figures/ndss/fig_cost_overhead}
  \caption{\textbf{Cost per DNP3 exchange.} (a) End-to-end response time per class; boxes span the
  quartiles and whiskers the full observed range. (b) Frames and captured bytes per exchange on the
  master-facing link, equal in the two arms.}
  \label{fig:cost}
\end{figure}

\textbf{Result.} In Figure~\ref{fig:cost}, the median response time rises by 22.7~ms for READ,
22.6~ms for SELECT and 21.2~ms for OPERATE. The added latency is close to, but not equal to, the
release budget, because it depends on how long the outstation itself took. On the master-facing
link each capture carries 1{,}448 frames and 130{,}708 captured bytes for 480 exchanges in both
arms, that is 3.017 frames and 272.3 bytes per exchange, so the mechanism moves packets in time
without adding any to that link.

\textbf{Scope.} This is a statement about the observed link. The switch also generates internal
blocker traffic that drives the release schedule; that traffic never appears on the master-facing
link and is not counted here.

\subsection{RO5: Protocol Preservation}
\label{sec:eval:ro5}

Across all 63{,}360 exchanges every request was answered with a well-formed response, and all
5{,}280 SELECT and OPERATE exchanges returned a success status. The external DNP3 workload
therefore completes unchanged under the mechanism, which is a precondition for deploying it in
front of a live outstation.

\subsection{Limitations}
\label{sec:eval:limits}

The evidence is one SEL-751A behind one Tofino-1, in one approximately five-hour campaign of 22
grouped runs on a single testbed, so it does not establish behaviour across days, devices, or
deployments. We evaluate transaction-class timing for one device and do not build a device-model
classifier, so nothing here shows that two devices become indistinguishable. DNP3 function codes
remain visible in plaintext, so the result concerns the timing channel and not the concealment of
operations. The relay-facing link is not instrumented, so the per-transaction hold, the release
toward the outstation, and physical actuation are configured rather than observed. A fixed budget
leaves a small tail of exchanges outside the target interval, which the fail-open path bounds
rather than eliminates. Finally, an adaptive adversary that retrains on obfuscated traffic recovers
part of the class signal from the difference between the two anchors.
