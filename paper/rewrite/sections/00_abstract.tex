\begin{abstract}
An adversary watching a power-grid control network can tell which device it is looking at from how
long that device takes to answer, because vendors implement the same function differently. The
relay cannot be modified, and existing traffic obfuscation targets a different feature: it
reshapes flow-level sizes and inter-packet times, whereas what identifies the device here is one
interval inside a single transaction.

We place the defense in the network instead. A programmable switch in front of the outstation
holds the device's acknowledgment and its response, releasing each at a deadline computed from one
common instant, the moment the outstation acknowledges the request. Because both deadlines come
from that one instant, the device's own processing interval cancels from the gap between the two
releases whenever the response arrives in time, so the interval an observer measures is one the
operator sets. The switch
forwards the packets it received, so both endpoints run unmodified and no DNP3 byte changes.

We implement this on an Intel Tofino-1 and evaluate it against one physical SEL-751A protective
relay over 63{,}360 exchanges. The measured interval settles on the configured value: its median
is the configured 4~ms and its sample variance falls from 6.808 to 0.394~ms$^2$. A classifier
trained on that interval before deployment is left at chance across READ, SELECT and OPERATE. An
adversary who retrains recovers much of that from a second interval the mechanism does not target
but does make more informative, and that residual bounds what the design achieves. The evaluation covers
transaction-class timing for a single device at a single configuration, and does not address
discrimination between device models.
\end{abstract}
