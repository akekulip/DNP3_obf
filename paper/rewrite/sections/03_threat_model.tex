\label{sec:threat}

\textbf{The adversary.} We assume a passive observer on the master-facing link, the adversary of
the fingerprinting attack we defend against~\cite{formbyWhosControlYour2016}, sitting where
Figure~\ref{fig:observation} shows. It records TCP and IP headers, segment sizes and arrival
times, and because DNP3 carries no transport security by
default~\cite{eastTaxonomyAttacksDNP32009}, it also reads the DNP3 function codes directly. It
neither modifies nor injects packets and cannot read the switch's internal state, the same passive
observer the traffic-obfuscation work we build on targets.

\textbf{What the adversary is looking for.} Reconnaissance precedes the attacks that matter here:
false data injection requires the attacker to know which devices it is dealing
with~\cite{liuFalseDataInjection2009}, and fingerprinting supplies that knowledge without the
payload, since the timing of the exchange carries it.

Following Formby et al.~\cite{formbyWhosControlYour2016}, two intervals fall in scope. The first,
the CLRT of a READ or of the SELECT phase of a control, measures the outstation's own processing
and carries the separation between the classes that Section~\ref{sec:bg} shows. The second is the
master-visible interval between an OPERATE's acknowledgment and its solicited response. The
observer also sees the request-to-acknowledgment interval, a median 0.56~ms on this device, and
the evaluation gives it to the classifier as well.

\textbf{What the evaluation measures.} We ask whether the timing of an exchange still reveals
\emph{which class of transaction} it carries, a three-class problem over READ, SELECT and OPERATE
with a chance level of 0.333 balanced accuracy. That per-operation timing profile is what a
fingerprinter builds, so the question is whether the profile survives the defense.

\textbf{Two adversary conditions.} The \emph{fixed} condition learns transaction classes from
undefended traffic and applies that model unchanged once the defense is deployed, the adversary the
reconnaissance setting describes. The \emph{adaptive} condition collects obfuscated traffic and
retrains. The plaintext function codes supply its labels, so it measures what remains learnable
once the defense is deployed.

\textbf{Research objectives.} We state the goal as five properties, which the evaluation answers
in turn.
\begin{itemize}
  \item \textbf{RO1 (read timing).} The visible CLRT of READ and of the SELECT phase of SBO is a
    configurable policy value rather than the outstation's own processing signature.
  \item \textbf{RO2 (control timing).} The master-visible OPERATE response-to-ACK interval stays at a
    policy value while the relay-facing hold is drawn from a configured codebook of 2, 6 and
    12~ms.
  \item \textbf{RO3 (timing leakage).} The timing features carry less information about the
    transaction class, and a fixed adversary that trained on undefended traffic is reduced to
    approximately three-class chance, which for READ, SELECT and OPERATE means 0.333 balanced
    accuracy.
  \item \textbf{RO4 (release policy and coverage).} The release budget, the range of policies the
    mechanism can realize, the fraction of traffic it can cover, and the residual it leaves are
    characterized rather than assumed.
  \item \textbf{RO5 (cost and protocol preservation).} We measure the latency the mechanism costs and the
    frames and bytes it adds, and the external DNP3 workload still completes: every request is
    answered and every control operation returns a success status.
\end{itemize}

The framework forwards every packet at its original size and leaves the function codes in
plaintext, so RO3 concerns the timing channel alone.
