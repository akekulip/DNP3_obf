\section{Implementation}
\label{sec:impl}

To evaluate the framework, we implemented it on an Intel Tofino-1 switch and placed the switch
between a DNP3 master and a physical protective relay. In this section, we describe the deadline and transaction state used by the
queueing mechanism, then present the testbed.

\subsection{Deadline and Transaction State}
\label{sec:impl:queues}
\label{sec:impl:walkthrough}

Section~\ref{sec:design:pipeline} describes the queue and pipeline mapping. Here we describe the
state that realizes those decisions. The program stores absolute deadlines on a 256~ns grid.
Each blocker reservoir contains 64 packets, which test the relevant deadline on every internal
return. ACK and response blockers use separate reservoirs, while their queues share one scheduler.
A deadline ends blocker recirculation; packets already queued still require service before release.

\textbf{Transaction State.} A fresh protected request records the transaction and arms both
return deadlines. A later acknowledgment cannot move those deadlines. The response enters its
held queue even if it arrives late, and its release clears the read-lane transaction. Blocker tags
allow ingress to reject tokens from an old transaction when they return. They do not remove the
service already consumed by tokens waiting in a queue.

\textbf{Control State.} SELECT prepares the control lane, and an admitted OPERATE selects its
command hold. Both lanes share the return-deadline registers, protecting one transaction at a time.
The control lane retains the released OPERATE generation until the next SELECT and drops a matching
retransmission. Consequently, it does not provide recovery of a command lost toward the relay
(Section~\ref{sec:eval:limits}).

\textbf{Holding Limits.} Blockers stop on expiry, stale state or exhaustion of their pass budget.
The control plane uses a horizon estimate $H=30.8$~ms to describe the supported hold, but this is
not an elapsed-time limit directly enforced by the data plane. Packets outside the protected
session and requests that cannot be admitted follow bypass paths. With timing disabled, the program
forwards packets without scheduled holds, giving the Timing OFF case.

\subsection{Testbed}
\label{sec:impl:p4}

\textbf{Switch Program.} The program has 1{,}584 lines of
P4$_{16}$~\cite{p4ccr2014} for the Tofino Native Architecture
(comments excluded), and we compiled it with the Barefoot SDE 9.13.2. It occupies all twelve ingress stages and
six egress stages of one pipeline, with 113 tables. Its state lives in one-entry registers, each accessed once per packet.
One 25~Gb/s port connects the master and one 1~Gb/s port connects the relay. Two further ports are
loopbacks without cables, one for the read lane and one for the control lane.

\textbf{Control Plane.} A control plane written in Python, around 900 lines in its entry module,
brings up the ports and the queues, configures the packet generator, and writes the release policy
into runtime tables and reads it back. An operator therefore changes the policy by writing table
entries rather than loading a new program. The control plane refuses any release offset at or above
the smallest of the timer and horizon bounds it is given, which is 30~ms on our testbed.

\textbf{Physical Device.} The outstation is an SEL-751A feeder protection relay, one of the DNP3
device classes that Formby et al.\ fingerprint~\cite{formby2016}.

\textbf{DNP3 Master.} The master issues READ polls and select-before-operate controls through a
guarded driver. Every control operation addresses an isolated control point, so no operation in the
evaluation moves a breaker.
