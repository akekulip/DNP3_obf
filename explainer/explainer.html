In-network defense · Intel Tofino-1 · DNP3 / SCADA

Making two grid devices look the same on the wire

A passive observer can fingerprint a DNP3 outstation from its TCP handshake, timing, and response sizes — before reading a single byte of payload. This is how one Tofino switch collapses those fingerprints, proven on real silicon.

byte-identical on silicon bf-p4c 9.13.1 / 9.13.2 no proxy · one switch SEL-751 · ION7550 · AB1400

01The problem

A device gives itself away before it says anything

A DNP3 outstation — a protective relay, a meter — answers polls from a master over TCP. An attacker who can only watch the traffic still wants to know which device is on the wire: a protective relay is a far more interesting target than a revenue meter. The device tells on itself in three ways, none of which is the payload.

  • How its TCP handshake looks. Every stack negotiates options — MSS, Timestamps, Window Scale, SACK — and lays them out differently per vendor. Our three physical devices had three distinct SYN-ACK layouts (the data_offset field alone was 11, 6, and 7).
  • How it times its answer. The SEL-751 sends a separate ACK and then the response a millisecond or two later; the ION7550 piggybacks the ACK. Both the delay and the two-packets-versus-one shape are fingerprints.
  • How big its answers are, and whether it does controls. Response sizes, segment counts, and the presence of SELECT/OPERATE all separate one device from another.

The ideal. Put one programmable switch in front of the outstation and make the observable traffic independent of the device — plaintext DNP3, one switch, no proxy, no second box. The honest boundary: the SEL-751 and ION7550 are different device classes (a separate-ACK relay that does controls, versus a combined-ACK read-only meter). Most fingerprints collapse cleanly; a few are structural. We say which is which.

02The mechanism

Attack the transcript one axis at a time

The observable transcript is a sequence of (gap Δ, size S, direction d). We convert each axis into a bounded win with its own mechanism, oracle, and hardware test — rather than claiming the whole transcript at once.

Handshake header — make every SYN/SYN-ACK canonical

The switch rewrites only the handshake: it strips Timestamps / Window-Scale / SACK, forces a single canonical [MSS] option, sets data_offset = 6, clamps MSS to 1460 (never raising it), canonicalizes the window, sets TTL 64, zeroes IP-ID on atomic datagrams, and recomputes both checksums. Anything it does not fully understand — TCP-MD5/AO, a SYN with payload, a fragment — it fails open. The rewrite is stateless and packet-bounded: no per-flow tables, no reassembly.

One correctness point that took an iteration: the rewrite must be symmetric. Strip options from the master's SYN but leave the outstation's SYN-ACK, and the ends disagree about window scaling. Because the switch strips both directions, both ends consistently negotiate "no options" — no desync — which is what lets it aggressively canonicalize the SEL-751's full-option SYN-ACK instead of failing open on it.

Timing — CLRT magnitude, and ACK-mode

The CLRT magnitude (the delay) is held to a public deadline so its distribution collapses (the accepted Defense 4 work). The ACK mode is a separate shape: the switch suppresses the outstation's standalone pure ACK (drop_ctl); the response that follows within the CLRT re-acknowledges the master, so the Case-A device now emits one packet, matching Case B. Safe for the request→ACK→response pattern within the timing budget; full robustness needs a light per-flow "response pending" bit.

Size and SBO

The READ-range primitive rewrites a request's object stop field to a public superset (identical request length), so the outstation emits a public-target-sized response with no inserted bytes — hence no TCP sequence translation. The SBO mechanism pads a SELECT/OPERATE with inert decoy control blocks, which does insert bytes and needs a per-flow 32-bit sequence-delta plus an ACK fix-up (oracle-verified).

03The Tofino implementation

Three stages, one program, and the idioms that actually compile

A Tofino program is a parser that pulls fields out, a match-action (MAU) section of tables that decide and rewrite, and a deparser that recomputes checksums and serializes out. The whole normalizer — handshake and ACK-mode together — is one ingress program.

The "obvious" way to write this does not compile, and the fixes are reusable Tofino lessons:

  • The counter. Twelve scattered ctr.count(i) calls each become an implicit table sharing one counter on overlapping paths — rejected, and at full nesting it crashed bf-p4c with a message-less internal error. Fix: one mutually-exclusive outcome index, counted once.
  • Arithmetic on emitted fields. Checking payload as total_len != 20+4·data_offset puts deparsed fields into a shift/add the backend can't place. Fix: a tiny data_offset→length const table (t_exp) and a plain equality.
  • Comparing two variables. A gateway can't test MSS > 1460. Fix: a range-match table (t_clamp) does the wide inequality in TCAM.
  • Deep nested gateways. Each leaf carries the whole path predicate and blows the input limit. Fix: precompute every deep predicate as a 1-bit flag.
  • The DNP3 CRC. The size mechanism recomputes the block CRC with the native CRCPolynomial(0x3D65, reversed, init0, xor 0xFFFF) hash extern — CRC-16/DNP (check value 0xEA82), run in the MAU.
  • Dropping a packet. ACK suppression is ig_dprsr.drop_ctl = 1.

Testing on real silicon without a second machine

  • In-switch pktgen → counters. The switch's own generator injects a crafted packet; a parser state skips its 6-byte header; the per-outcome counters confirm the ASIC classified it.
  • bf_kpkt CPU netdev → byte capture. Swapping the packet driver exposes the CPU port as a Linux netdev (ens1); a loopback build lets a raw socket inject a device SYN-ACK and read back the exact normalized bytes the pipeline produced.

The last row is the point. The bytes leaving the chip for all three devices are identical — data_offset=6, options=020405b4 (MSS 1460), window=8192, ttl=64, ip.id=0 — and only the per-connection 5-tuple, sequence/ack, and checksums differ, which are flow state, not device identity. (One honest gotcha: comparing whole frames showed a spurious 2-byte diff that was minimum-frame padding beyond the IP length; bound the compare to total_len and it vanishes.)

This is why the overall verdict is a conditional "no-go on the full transcript": several axes are clean bounded wins proven on silicon, but universal invariance across two device classes runs into structural residuals a single-switch, no-proxy design bounds. The demonstrated program is to keep converting axes into bounded, hardware-proven wins.

05Reproduce it

Run the oracles, compile the pipeline

# oracles (pure Python, no hardware)
$RESEARCH_PYTHON experiments/exp2_handshake_normalizer/tests/oracle.py               # 28/28
$RESEARCH_PYTHON experiments/exp2_handshake_normalizer/tests/indistinguishability.py # YES
$RESEARCH_PYTHON experiments/exp3_ack_mode/oracle_ackmode.py                         # 10/10

# compile (bf-p4c 9.13.1)
bf-p4c --std p4-16 --target tofino --arch tna -o /tmp/out \
    experiments/exp2_handshake_normalizer/p4src/combined_normalizer.p4               # 0 errors

# silicon byte capture (switch host, bf_kpkt CPU netdev)
sudo python3 evidence/hardware_9132/capture.py                                       # byte-identical
