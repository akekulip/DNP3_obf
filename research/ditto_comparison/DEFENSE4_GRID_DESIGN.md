# Defense 4 — the slotted release grid: full technical map

**2026-08-04. Design study only; no hardware touched, nothing built. Numbers in §3 are
computed from 400 native physical transactions we already hold (three campaigns against the
SEL-751). Companion: `DITTO_VS_DEFENSE3.md`.**

---

## 1. The idea in one paragraph

Defense 3 releases the held acknowledgement at `t_ACK + D`. That instant is a function of
**`t_ACK`, a device-generated arrival**, so the relay's own ACK latency `a` is carried through
into the observable and REPORT §12.4 measures READ→ACK separability of 1.000 at every
`D ≥ 4 ms`. Defense 3 *relocates* the leak. Defense 4 changes what the release is a function
of: packets are released **only on edges of a grid `t_k = t_0 + kT` generated by the switch's
own clock**. Nothing a device did enters the release instant, so no device-dependent quantity
can appear in any observable. The mechanism that does the holding — a strict-priority blocker
reservoir starving a hold queue — is unchanged and already silicon-proven; **only the anchor
changes**.

Ditto reaches the same property from the other side (a fixed pattern at a fixed rate), which
is why it has no relocation problem. But Ditto's grid and our deadline hold are
**substitutes**: grafting a coarse grid downstream of our hold makes the hold dead weight,
and a grid fine enough to preserve our 1.72 µs release tail needs ~580 kpps of chaff. So this
is an *anchor change*, not an architecture import.

## 2. The observable model — what is provably device-independent

Let `a` = relay READ→ACK latency, `c` = relay CLRT (ACK→RESPONSE), both device-dependent.
Let `φ` = phase of the master's READ relative to the grid. Let `τ ≈ 1.72 µs` = the measured
release tail, `N` = slots the transaction is held for.

### 2.1 Why the READ direction must be gridded — the `a/T` leak

If only the relay→master direction is quantised, the READ arrives at phase `φ ~ U[0,T)` and
the ACK is emitted at the first edge after `φ + a`:

```
observed READ→ACK  =  T − φ        if φ + a < T
                   =  2T − φ       otherwise
P(observed > T)    =  a / T
```

The two ranges are disjoint, so the adversary estimates **`a = T · P(observed > T)`** by
counting slot crossings. At `T = 20 ms`, a device with `a = 5 ms` crosses at 0.25 against
0.023 for the SEL-751 — separable in tens of samples. **Quantising one direction is not a
partial defense; it is a different leak.**

Holding the master→relay READ to the next edge sets `φ = 0` by construction, and then:

| observable | value under Defense 4 | device terms |
|---|---|---|
| READ egress (relay-facing) | `t_k` | none |
| READ→ACK (master-facing) | `N·T` exactly | none |
| CLRT | `τ` (co-release) or `T` (split-slot) | none |
| READ→RESPONSE | `N·T + τ`, or `(N+1)·T` | none |
| inter-poll interval | master's own schedule, quantised | none |
| **slip indicator** | `1` iff `a + c > N·T` | **`a`, `c`** |

**Every device term is confined to the slip indicator.** That is the whole security claim, and
it reduces to a measurable probability.

### 2.2 Two slot structures

**(A) Co-release.** READ at edge `k`, ACK **and** RESPONSE both at edge `k+N`. Requires
`a + c ≤ N·T`. Observed CLRT ≈ `τ` — constant, but anomalously small (this is Defense 3's
present signature).

**(B) Split-slot.** READ at `k`, ACK at `k+1`, RESPONSE at `k+2`. Requires `a ≤ T` **and**
`c ≤ (N−1)·T` separately. Observed CLRT = `T` — constant, and *plausible*: every protected
device looks like one synthetic device with `a = T`, `c = T`.

(B) costs one more slot of latency and is the better security story, because the output
resembles a device rather than resembling a switch. Recommend (B), keep (A) as the
low-latency variant.

### 2.3 What still leaks

1. **The slip channel.** If `a + c > N·T` the response lands a slot late; the slip *rate*
   leaks `c` at granularity `T`. Quantified in §3.
2. **Detectability.** Total, and acceptable. The goal is indistinguishability *among protected
   devices*, not concealment of the defense — Ditto is equally detectable and says so.
3. **Intra-burst ordering** between concurrent sessions leaks relative `a+c`. Mitigate with
   one grid per device group, or quantify and disclose.
4. **Everything non-timing**: response size and structure (see the companion document — closed
   for a different, information-theoretic reason), TCP stack fingerprint, ACK mode.

## 3. Parameter derivation from measured data

400 native transactions, three campaigns (`evidence/physical/`, `evidence/physical_repaired/*`):

| quantity | median | p95 | p99 | max |
|---|---|---|---|---|
| `a` READ→ACK | 0.453 | 2.914 | 3.518 | 3.731 ms |
| `c` CLRT | 2.828 | 12.222 | 13.134 | 13.175 ms |
| **`a + c`** | **3.406** | **13.580** | **16.163** | **17.662 ms** |

Measured slip rate `P(a + c > N·T)`:

| `T` | `N` | `N·T` | slip (n=400) | covers observed max? |
|---|---|---|---|---|
| 8 | 2 | 16 ms | **0.0125** | no |
| 8 | 4 | 32 ms | **0** | yes |
| 10 | 3 | 30 ms | **0** | yes |
| **16** | **2** | **32 ms** | **0** | **yes** |
| 20 | 2 | 40 ms | 0 | yes |

**`N·T ≥ 32 ms` is the binding requirement.** `T = 16 ms, N = 2` is the recommended operating
point: zero slips observed, and it leaves headroom for the connection-cold first poll
(~21–25 ms, which the campaigns exclude because they reuse connections).

Statistical honesty: zero slips in 400 samples bounds the true rate at **≤ 0.75 % (95 %, rule
of three)** — it does not establish zero. The slip rate must be re-estimated with a block
bootstrap **over connections**, not transactions, because `a` and `c` are correlated within a
session.

### 3.1 The fail-open horizon must be raised — this is a hard blocker today

`H = B·K/rate`. At the shipped `B = 18 000`, `K = 64`: **`H = 30.802 ms`**, which is *less
than the required `N·T = 32 ms`*. The budget would expire before the grid released, so the
defense would fail open on every transaction.

Required: `H > N·T + a_bound + t_detect + t_drain + t_tail + M ≈ 32 + 6 = 38 ms`
→ `B > 22 206`. Ceiling from the RTO floor: `H < RTO_min − margin = 180 ms` → `B < 105 187`.

**Recommend `B = 30 000` → `H = 51.3 ms`**, comfortably inside both bounds. The
generation-wrap constraint `16·T_poll,min > H + t_drain + M` gives `3200 ms > 51.4 ms` —
satisfied with three orders of magnitude to spare. `budget` is a `bit<32>` field, so no width
problem. `control/parameter_policy.py` becomes the authority for `(T, N, K, B)` instead of `D`.

### 3.2 Latency budget

Worst-case added latency `(N+1)·T = 48 ms` at `T = 16, N = 2`, against a **measured RTO of
~200 ms** — 24 % of RTO, at the edge of the ≤¼ guideline. The DNP3 application-layer timeout
must also be checked against 48 ms. If too tight, `T = 10, N = 3` gives `N·T = 30 ms` and
`(N+1)·T = 40 ms` at the cost of one more slot of state.

## 4. Mechanism on Tofino-1

### 4.1 The grid tick replaces timestamp arithmetic

Defense 3 computes `t_ACK + D` into a 32-bit deadline register and compares each token's
timestamp against it — the source of the §8.1 large-immediate SALU hazard and of a whole
dependency level.

Defense 4 needs no timestamp arithmetic at all. A **periodic pktgen app fires every `T`**;
that tick packet increments a small **epoch counter `E`**. A transaction admitted during
epoch `e` records `target = e + N`. A blocker token dies when `E ≥ target`.

Consequences:
- The comparison is over a **small integer** (epoch, a few bits) rather than a 32-bit
  timestamp, so the large-immediate SALU trap does not arise.
- `reg_deadline` and its arithmetic are **deleted**.
- The tick is a self-clocked metronome, input-independent — measured at **100 pps ± 1** on
  this silicon.
- The TM shaper is *not* usable for this: measured, it hits the correct average at 100–2000
  pps but the **cadence clumps with a ~4.4 s period at R ≤ 200 pps** and is smooth only above
  ~600 pps; it is a rate *cap*, not an up-pacer, so it can never manufacture cadence for a
  sparse flow.

### 4.2 Nested strict priority holds both directions on ONE loopback port

The obvious objection to gridding both directions is that strict priority is a *total order*
on a port, so you cannot release one queue while holding another. The resolution is to
interleave the blockers with the hold queues:

| priority | occupant | dies / drains at |
|---|---|---|
| 7 | **blocker set B** (self-recirculating) | epoch tick `k` |
| 5 | `Q_HOLD_READ` (master→relay READ) | drains at `k` |
| 3 | **blocker set A** (self-recirculating) | epoch tick `k+N` |
| 0 | `Q_HOLD_REPLY` (ACK, then RESPONSE) | drains at `k+N` |

While B is alive nothing moves. B dies at edge `k` → `Q_HOLD_READ` drains (now the highest
non-empty queue) → the READ goes to the relay. A is still alive at priority 3, so it starves
`Q_HOLD_REPLY`. A dies at edge `k+N` → the reply drains, ACK before RESPONSE by FIFO order.

**Three strict-priority levels with nested blockers are already proven on this silicon**
(IBSPG Part 11, 100/100 both injection orders). This design needs four levels — the increment
must be verified, but the primitive is not new. Crucially it means **no additional loopback
port is required**; a Ditto-style two-pass architecture is not needed because our schedule has
one level (gate open / gate closed), not two.

### 4.3 Resource ledger

| item | change vs Defense 3 |
|---|---|
| `reg_deadline` + deadline arithmetic | **removed** |
| response-authorisation table (today the single largest stage contributor: one table + one dependency level) | **removed or simplified** — the grid holds everything from the admitted 5-tuple regardless of match |
| epoch register + comparison | +1 small SALU |
| second blocker class | +2–3 table entries, +1 pktgen app |
| grid tick app | +1 pktgen app (periodic) |
| `Q_HOLD_READ` + master-direction branch | +1–2 tables, possibly +1 dependency level |
| **predicted ingress stages** | **7–8, against 10 today** — a *prediction*; only `bf-p4c` settles it |

Constraints that bind: pktgen has **8 apps per pipe** and we use 3 (headroom fine); the tick
app must be armed in **both pipes** (§8.4 trap: enabling device-wide arms both, and a
timer-triggered app fires in both); PHV groups **B0-15 and W0-15 are fully exhausted (16/16)**,
so any new 32-bit operand pair must land in W32-47 (14 containers free).

### 4.4 The ordering invariant must extend to the new direction

Defense 3's invariant requires every protected packet to share ingress port, dp8 qid, **equal
loopback pass count** and final egress qid. An arm that skips a pass overtakes a held packet
for the whole 1.72 µs release tail — this has already bitten twice, once measured at a
bypassed duplicate RESPONSE committing **1.0014 ms ahead** of the held ACK. Defense 4 adds a
whole direction, so the invariant must be re-established for READ-path bypass and fail-open
arms as well.

## 5. Hurdles, ranked by severity

| # | hurdle | severity | resolution |
|---|---|---|---|
| 1 | **`H = 30.8 ms < N·T = 32 ms`** — the shipped fail-open budget cannot support the grid | **blocking** | raise `B` to ~30 000 (`H = 51.3 ms`); re-derive the whole admissibility surface in `parameter_policy.py` |
| 2 | **Gridding the READ direction is new work** — a direction Defense 3 never touches | high | nested-priority design (§4.2); needs the 4-level priority increment verified |
| 3 | **Slip rate is an upper bound, not zero** (≤0.75 % at 95 %, n=400) | high | block-bootstrap over connections; treat the slip rate as *the* security metric and report it |
| 4 | Added latency 48 ms = 24 % of the 200 ms RTO; DNP3 app timeout unchecked | medium | verify the app timeout; fall back to `T=10, N=3` (40 ms) |
| 5 | Connection-cold poll (~21–25 ms) not represented in the campaign data | medium | `N·T = 32 ms` covers it by construction; verify with a deliberate connection-open capture |
| 6 | Ordering invariant across the new direction and the bypass/fail-open arms | medium | extend the Gate-2 rubric before any silicon run |
| 7 | 4 strict-priority levels (3 proven) | medium | control-plane readback + a queue microbench, no DNP3 needed |
| 8 | Stage budget: predicted 7–8 but stages 7–8 saturated at 16/16 LTIDs today | medium | ACT leaves can land in stages 10–11 (empty); compile-only probe settles it |
| 9 | Concurrency: sessions sharing a grid leak relative `a+c` via intra-burst order | low | one grid per device group, or quantify and disclose |
| 10 | Grid tick must fire in both pipes | low | known trap, already handled in Defense 3's pktgen config |

**Two Defense 3 problems that the grid removes for free:** the ~10 s TCP keepalives that
qualify as pure ACKs stop being a re-arm hazard (the grid simply holds them one slot and
forwards them — the disarm bug disappears rather than being patched), and the fixed-`D`
large-immediate SALU hazard disappears with the deadline register.

## 6. Experiment plan

**E0 — Gate (hours, no hardware, data in hand).** Compute post-Defense-3 mutual information /
classifier accuracy for CLRT, response size and inter-arrival over the 400 defended
transactions. Confirms empirically that the timing axis is the only one worth attacking and
that the size axis has no target. **This precedes everything.**

**E1 — Slip-rate estimation (hours, no hardware).** Block bootstrap over connections on the
`a + c` distribution; produce a slip-rate confidence interval per `(T, N)`; re-derive the
`(T, N, K, B)` admissibility surface in `parameter_policy.py`. Output: the parameter table
the design is built against.

**E2 — Compile-only probe (no switch load).** Build the grid skeleton and read
`table_summary.log` for the stage count. Turns "predicted 7–8" into a number. Non-destructive;
`bf-p4c` runs off-switch.

**E3 — Queue microbench (switch, gated).** Verify 4 nested strict-priority levels and that
`Q_HOLD_READ` drains at tick `k` while `Q_HOLD_REPLY` stays starved until `k+N`. No DNP3, no
relay — a pure scheduling test.

**E4 — The falsifier: synthetic device population (switch, gated).** Drive the grid with
switch-generated READ/ACK/RESPONSE triples at three programmed `(a, c)` profiles —
SEL-751-like (0.45, 2.85 ms), slow-ACK (5, 0.5 ms), slow-response (0.4, 12 ms) — capture at
the master port, and run the §12.4 classifier **between profiles**. Defense 4 claims
device-independence; it survives only if every pairwise score sits at the ~0.51 drift floor on
every feature (READ→ACK, CLRT, READ→RESPONSE, and departure timestamp mod `T`).

**This is the experiment Defense 3 structurally could not run.** REPORT open item #3 records
"a second separate-ACK device — not available" as blocking the anonymity question. Under a
grid, device-independence is a property of the *release rule*, not of the device, so a
synthetic population tests it. It is a **sufficient falsifier, not a sufficient confirmation**
— the headline anonymity claim still needs a real second device.

**E5 — Live validation against the SEL-751 (switch + relay, gated).** The existing Gate 2–4
rubric plus the new ordering invariant, then a D-sweep analogue over `T`.

## 7. What would make this publishable

The contribution is not "a shaper for ICS". It is:

1. **Event-anchored versus schedule-anchored defenses.** A defense whose release instant is a
   function of a device-generated arrival *relocates* the leak; one anchored on the defender's
   own clock erases it. Defense 3 is the measured example of the first (§12.4, separability
   1.000) and Defense 4 the constructive example of the second — **measured on the same
   hardware against the same relay**, which is a comparison almost no paper in this space has.
2. **The `a/T` slot-crossing result.** Quantising one direction converts a latency leak into a
   crossing-rate leak of exactly `a/T`. It is small, exact, and generalises to any one-sided
   quantiser.
3. **The cost-model inversion.** BuFLO, CS-BuFLO, Pacer, NetShaper and Ditto all trade privacy
   against overhead because their traffic is bursty and high-rate. At 5 pps and 200 B the
   provably optimal defense — emission on a content-independent schedule — costs ~10 kbit/s,
   so **we can afford the ideal instead of a heuristic**, and the paper's job becomes
   quantifying exactly what still leaks.
4. **The envelope boundary** (companion document): shaping is only meaningful inside a
   cryptographic boundary; a non-cooperating middlebox on a plaintext link cannot obtain size
   privacy, for two independent reasons. Ditto is the positive case, we are the negative one,
   and the pair is the result.
