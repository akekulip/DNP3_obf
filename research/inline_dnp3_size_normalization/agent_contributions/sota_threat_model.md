# SOTA & Threat Model — In-Network DNP3 Size Normalization

*Contribution from sdn-networks-expert (2026-07-18). Sources verified via WebSearch/WebFetch + PDFs this session (arxiv/semantic-scholar MCP was not invocable from the agent's tool surface). Nothing cited from an unopened source.*

## 0. Novelty verdict (lead)
The defensible new thing is NOT "pad a packet in a switch" (exists). It is **append-only, integrity-correct, application-semantics-preserving size growth delivered to a NON-COOPERATIVE TCP endpoint, from a SINGLE commodity switch, with no de-obfuscator on the far side and no full TCP proxy.** Every verifiable line-rate in-switch shaper either (a) needs a cooperating far-end switch/host to strip padding before the real endpoint (ditto), (b) manipulates header-field covert channels not app payload size (NetWarden), or (c) moves REAL bytes for efficiency, not semantically-valid filler an unmodified receiver must accept and ignore (PayloadPark, P4 aggregation). DCRN-size occupies the empty cell: padding is real DNP3 a stock master parses and discards, added by one switch, only the final grown packet on the wire.

**TWO GATES, both must be PROVEN not asserted:**
1. **Semantic transparency at a non-cooperative master** — will a real DNP3 master accept appended constant filler blocks without error/RST/SOE-corruption/link-NACK? (Empirical; the rig answers it.)
2. **★ Per-flow TCP seq/ack delta (the finding to carry from the start).** Injecting B bytes into a live outstation→master TCP stream is NOT transport-stateless: it forces **monotonic seq/ack rewriting for the REST of the connection** — the switch must ADD the cumulative byte-delta to every subsequent outstation→master seq and SUBTRACT it from every master→outstation ack, per-flow, with checksum fixups, and the delta ACCUMULATES across every padded response. Lighter than a proxy (no TCP termination) but real per-flow state on EVERY packet of the flow, both directions. NetWarden proves this per-flow seq/ack register bookkeeping is Tofino-feasible at line rate. Must be in the design from the start, not bolted on.

Frame the contribution around those two → survives review. Frame it as "we pad packets in P4" → a reviewer cites ditto and rejects.

## 2. Threat model
Adversary: passive on-path observer DOWNSTREAM of the switch (switch→master / WAN). Cleartext DNP3/TCP → reads TCP payload lengths + DNP3 link structure. Features: per-response total size, TCP segment count + per-segment sizes, DNP3 frame count, timing. Goal: classify device (size-only ~0.99).
Placement assumption (state explicitly): switch at outstation edge; an observer UPSTREAM (outstation→switch) sees the un-padded response → defense void. Protected region = the wire on the MASTER side of the switch (same assumption ditto makes).
**Observer sees only the FINAL grown packet — confirmed.** Recirc passes loop through the TM back to ingress on an internal recirc port; intermediate passes NEVER egress a front-panel port, can't be mirrored externally. Advantage over chaff (ditto adds visible countable dummy packets); the carousel adds ZERO new packets, enlarges one real packet.
Residual fingerprints (honest): (a) **append-only ⇒ target must be the POPULATION MAXIMUM** (per-device targets would themselves leak → GLOBAL target; overhead = mean inflation to global max, acceptable at poll rates); (b) TCP seq/ack rewrite correctness (wrong → dup-acks/RST, loud + broken link — make-or-break); (c) master reaction to filler (reject → NACK/reset/SOE corruption, worse than the size leak); (d) segment structure if target > MSS (§3).
Why non-cooperative is the interesting case: a cooperative-endpoint tunnel trivially normalizes size but is deployment-infeasible for OT (closed embedded RTUs/IEDs you can't modify; third-party SCADA masters you don't own) — the boring solved model. The novel/useful case = NEITHER endpoint cooperates → a single switch injects bytes a stock master accepts + a stock outstation never learns about. That's why byte-preservation was relaxed to append-only integrity-correctness rather than solved on an endpoint.

## 3. Segmentation + MSS ceiling
Size has two joint sub-features: total bytes + segment/frame structure. DNP3 app responses → transport link frames (≤292 B, 16-byte data blocks + per-block CRC) → TCP re-segmented at MSS (~1460 B).
- **Target ≤ MSS → single-segment padding suffices** (append filler to one segment, emit ONE packet; size + segment-count normalized together for free). **SWEET SPOT — target this first.** Most DNP3 poll responses are tens–low-hundreds of bytes.
- **Target > MSS → size + segment-count coupled** (reaching target = synthesizing additional full segments, each a separate packet with its own seq; segment count/sizes become the fingerprint → need segment-count normalization too = the split/pace line in "emit fixed number of segments" mode).
Recommendation: choose the global target as the smallest value dominating the population's discriminative mass, keep ≤ MSS if possible so the carousel stays single-segment.
Composition: DCRN owns WHEN (timing recirc-hold); split/pace owns segment boundaries/count; the carousel is the missing SIZE actuator — the one operating BEYOND byte-preservation. The prior negative ("no byte-preserving DNP3 padding, size not closeable") holds BECAUSE byte-preservation forbids adding bytes; the carousel resolves it by weakening the invariant from "preserve every byte" to "append-only, integrity-correct, semantically inert" — strictly weaker + achievable. Three orthogonal actuators over one per-response policy {target_size, segment_plan, release_schedule}.

## 4. Contribution statement
"The first non-cooperative, integrity-correct, application-semantics-preserving response size-normalizer for a real industrial protocol (DNP3), realized entirely in a commodity RMT data plane (Tofino-1) via an append-only recirculation carousel — no cooperating de-obfuscator, no end-host modification, no full TCP-terminating proxy, only the final grown packet on the wire."
Must beat: drive size-only (~0.99) + joint size+timing+segmentation classifier → chance (1/K), while (a) preserving byte-exact semantics of the REAL response, (b) zero master-side errors/RST/retransmit/SOE-corruption, (c) within recirc/PHV/SALU budgets at line rate, (d) no cooperating far end.
Boundary sentence: a store-and-rebuild PROXY makes this easy + uninteresting; the contribution is doing it as an INLINE, NON-TERMINATING, TRANSPARENT transform in the switch ASIC — which is what makes the seq/ack-delta + constant-CRC/constant-checksum-delta machinery necessary + novel.

## 5. Architecture recommendation — build A
**A. Pure-switch carousel (Tofino-1 only) — RECOMMENDED, the novelty vehicle.** Parse DNP3 link LENGTH at fixed offset in TCP payload → decide append count → recirculate appending constant filler block(s)/pass with precomputed constant CRC + RFC-1624 incremental TCP-checksum delta → maintain per-flow seq/ack delta register (NetWarden-style) translating subsequent outstation seq + master ack for the connection's remaining life. Only genuinely single-switch, transparent, non-cooperative option; lowest latency; THIS is the contribution.
Binding constraints for p4-dataplane-engineer: (1) parsing link LENGTH at fixed offset = cheap; locating END of a MULTI-frame response needs the transport FIN bit + is harder → **single-frame responses = sweet spot**; (2) PHV/header budget — large single append can exceed parser handled-header budget → spread growth over MULTIPLE SMALL recirc passes; (3) recirc ~tens of ns/pass + shared bandwidth, fine at DNP3 poll rates; (4) SALU/registers — one stateful op/stage for seq/ack delta add + checksum delta; flow-table scale = concurrent outstation connections (tens–hundreds → trivial); (5) OPEN EMPIRICAL RISK = stock master accepting filler, validate on rig BEFORE writing P4.
**B. Switch + DPU/slow-path hybrid — FALLBACK.** Fastpath does single-segment common case; DPU/CPU does multi-frame reassembly + semantic filler + resegmentation for hard cases (NetWarden fastpath/slowpath precedent). Keep the DPU strictly ASSISTIVE (filler templates, offline master-model validation), NEVER TCP-terminating (termination = proxy = forfeits novelty). Use only if A can't cover the response distribution.
**C. Upstream/cooperative endpoint — REJECT but name.** Trivially normalizes size but requires modifying a closed OT endpoint (infeasible) + collapses into the solved cooperative-tunnel model (uninteresting threat model). One sentence to dismiss.
**Bottom line: build A.** Gate the P4 work behind ONE rig experiment: does the real DNP3 master on Hulk accept appended constant filler blocks without error/RST/SOE-corruption? YES → primitive real, A is the paper. NO → fallback B (assistive DPU, per-response semantic filler) — still novel, heavier claim.
