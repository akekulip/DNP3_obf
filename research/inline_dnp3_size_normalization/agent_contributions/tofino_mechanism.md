# In-Network DNP3 Size-Normalization on Tofino-1 — Mechanism Research

*Contribution from p4-dataplane-engineer (2026-07-18). Design/analysis only — nothing compiled/run. Tags: [L] confirmed from working lab code · [V] vendor/standard · [M] rig · [P] paper · [I] inference · [H] hypothesis. A first bf-p4c compile on switch SDE 9.13.2 is the only proof of stage/SALU/PHV fit.*

## 0. Verdict — BUILDABLE-WITH-X
The seed "append-only recirculation carousel" is buildable (every primitive is already in lab code) but is the WRONG DEFAULT, and its named crux ("trailer after unparsed payload") is NOT the real obstacle. Three corrections:
- **X1 — PREPEND a benign frame, don't APPEND a trailer.** TNA physically cannot emit a header after the unparsed residual [V]; parsing the payload to enable a true trailer is PHV-prohibitive [I]. Resolution exploits DNP3-over-TCP self-delimiting framing (0x0564 start + LEN): place the constant pad frame BEFORE the real response in the segment → `Eth|IP|TCP|[pad frame(s)]|real DNP3 response`. This is GridCloak's proven pad-before-inner geometry [L]; DNP3-semantically equivalent to a trailer (master reads benign frame, discards, reads byte-identical real response).
- **X2 — Prefer a one-pass conditional-emit LADDER over the recirc carousel.** GridCloak already emits a VARIABLE number of pad headers in one pass via conditional setValid() [L]. For the bounded DNP3 size range this normalizes size with NO recirculation. The carousel earns its keep only for large pad (PHV economy) or when co-running with DCRN (already recirculates on dp68).
- **X3 — Add the per-flow TCP sequence-space translator (the genuinely-new hard element the seed under-weighted).** Adding bytes to a live TCP flow desyncs seq accounting → correctness needs a per-flow cumulative offset Δ (forward seq += Δ, reverse ack -= Δ) + runtime-Δ TCP-checksum fixup. Stateful per-connection translator — lighter than a proxy (no reassembly/buffering/termination) but IS connection state, and it (not the CRC) is what a first build must prove.

No new TNA construct needed. The two externs the thesis leans on (CRC-16/DNP + IP/TCP Checksum()) are already used TOGETHER on a DNP3-over-TCP response in `p4_decoy/src/dnp3_decoy.p4` [L]. Residual risk = arithmetic lowering (runtime-Δ guarded carry, Class-6 zone) + TCP edge cases (retransmit/SACK), resolvable only at first compile + first rig run.

## 1. Framing
Size normalization = padding UP = adding bytes → two consequences: (1) **adding bytes to a TCP flow is inherently connection-stateful** — the outstation counts exactly the bytes it sent; injected bytes must be accounted for in BOTH directions for the connection's life or the outstation sees a future-ACK → challenge-ACK/RST (loudest tell + IDS trip). Unavoidable for ANY byte-adding size defense. (2) **the real DNP3 response bytes are never modified** — the primitive adds a constant envelope; the response stays the deparser residual → byte-identical. Byte-preservation survives at the semantic-content level even though this phase alters the outer TCP/IP envelope + total length.
Rejected seq-translation-avoiders: TCP/IP options (cap 40 B, anomalous on data segment); Ethernet trailer padding (≤60 B); separate pad segment (needs correct seq/ack anyway).

## 2. Kernels
**K1 trailer-after-unparsed-payload (the named crux):** UNSOLVABLE in one pass AND doesn't need solving — reframe append→prepend. TNA deparser emits emit() headers in program order then the unparsed residual automatically; no API to emit after residual. Making payload a parsed header (empty residual) costs most of Tofino-1's ~512 B PHV. The seed's two goals ("payload never in PHV" + "append at tail") directly contradict. Resolution: parse only Eth|IP|TCP (~54 B); emit pad header(s) BETWEEN TCP and residual → GridCloak's exact geometry (`ethernet, gc_obf, pad256…pad1, ipv4, l4_ports` with DNP3 payload as residual after pads) [L]. Pad frame(s) compile-time constant → header/data-block CRCs precomputed + baked in, no in-dataplane CRC. Real response stays residual → byte-identical. **Which TNA construct emits after opaque payload? NONE — you emit constant pad headers BEFORE the residual; DNP3 framing makes before ≡ after.** Open hand-off (not a dataplane problem): the constant pad bytes must be DNP3-benign + Zeek-clean. Leading candidate: a **header-only (10 B) DNP3 link frame addressed to a BLACK-HOLE link address** — master filters on its own link address, silently discards a frame not addressed to it [V] → no application effect, no reply, well-formed CRC-valid frame Zeek parses. Needs DNP3-line sign-off + live master/Zeek test; dataplane is agnostic to which constant bytes it carries. Fallback if no inert frame exists: Variant β.
**K2 CRC-16/DNP:** fully lab-proven. `p4_decoy/dnp3_decoy.p4` [L]: `CRCPolynomial<bit<16>>(coeff=0x3D65, reversed=true, msb=false, extended=false, init=0, xor=0xFFFF)` + `Hash<bit<16>>(CUSTOM, poly)`; matches `dnp3_crc.py`; stamps 6-field DLL-header CRC + 16-byte block CRC with crc[7:0]++crc[15:8] byte-swap; separate Hash instances per tuple shape (Class 7). For the recommended constant-frame variant the CRCs are precomputed host-side + baked in → extern not invoked (simplification win). Variant β's header-CRC recompute (LEN change, 6-field) is also proven by crc16_dnp_dl.
**K3 TCP/IP checksum:** IP easy + lab-proven (header-only, all fields in PHV → wholesale Checksum() or constant delta). **TCP must be INCREMENTAL, never wholesale** — Checksum() sums only PHV fields, the real payload is the unparsed residual (NOT in PHV). p4_decoy recomputes TCP wholesale only because it parses a fixed 16-byte skeleton. Incremental update = (a) constant pad-bytes + pseudo-header-length delta → CONSTANT ones-complement delta → guarded two-case constant add (Class-6-safe); (b) **seq/ack Δ → RUNTIME addend** → RFC-1624 folding with a runtime delta = **Class-6 silent-ICE neighborhood, the single highest arithmetic risk**, native-ALU lowering must be confirmed at first compile. Never read the residual payload for the checksum.
**K4 recirc-count:** only for the carousel; the ladder needs none (pad chosen + emitted in one pass). Composes with DCRN: carousel carries pass_count in recirc metadata (bridged, like DCRN), recirc out dp68 while pass_count < target, then egress dp8, max-pass fail-open. When BOTH run: merge into ONE pass-count state machine on dp68 (release predicate: size satisfied AND deadline met) — avoids two loops reordering.
**K5 MSS/segmentation:** MSS is advisory for the sender; receiver accepts up to MTU. Hard ceiling = MTU 1500 (beyond → IP fragmentation, forbidden). DNP3 link frame ≤292 B [V]; ~1150 B sub-MTU headroom → buckets up to ~1400 B. Policy: fixed bucket ladder {128,256,512,1024} B, pad up to smallest bucket ≥ actual s.t. segment+pad ≤ MTU. **Fail-open** if actual > largest sub-MTU bucket → forward unpadded (never drop/fragment/corrupt) — a malformed/oversized frame trips Zeek dnp3.
**K6 resource (one-pass ladder, ~5-6 of 12 ingress stages [I]):** S0 parse Eth/IP/TCP + derive dir/is_dnp3_response/region-length; S1 flow_id=Hash(5-tuple) [Class 7, one instance]; S2 region-size→bucket via RANGE TABLE (size sliced ≤20b, Class 2, avoids gateway < Class 1) + read per-flow Δ; S3 conditional pad-header setValid() (GridCloak ladder) + Δ+=pad_len SALU [Class 8 controller-seed, Class 3 bit<8> flags]; S4 ip.total_len += pad_len + seq/ack ±Δ (single-runtime-operand adds, Class 5); S5 IP checksum (constant/wholesale) + TCP checksum incremental (constant delta ⊞ runtime-Δ delta) [**Class 6 — the risk**]; deparser emit eth,ip,tcp,pad-subset,[residual] (GridCloak-proven). Registers: reg_flow_delta (Register<bit<32>,bit<16>>, 65536 flows), bucket range table (~4), forward table, 1 Hash. **PHV is the real ladder cost:** each emitted pad byte consumes PHV (GridCloak pad128=128 B PHV; Tofino-1 ~512 B) → ladder comfortable ≤128-256 B pad, carousel wins beyond (O(1) PHV, O(passes) recirc, reuse dp68 self-clock ~0.003-0.6% budget).

## 3. Alternatives
- **α — prepend constant benign DNP3 frame(s) via one-pass conditional-emit ladder → RECOMMENDED.** Simplest, lowest latency, max reuse of GridCloak geometry; no recirc, no in-dataplane CRC (constant frame). Cost: PHV grows with largest bucket; still needs X3.
- **α′ — same via recirc carousel (one constant block/pass on dp68).** For LARGE pad (PHV-thrifty) or co-running with DCRN. The seed thesis corrected: value is PHV economy, not solving deparser order; each pass PREPENDS one more constant block ahead of the growing residual.
- **β — grow the REAL frame's data blocks (append inside frame).** One DNP3 frame, avoids the benign-frame semantic question. Cost: touches real LEN → header-CRC recompute (proven crc16_dnp_dl) + appended bytes must be app-valid objects the master tolerates (semantically messier, higher IDS risk). [NOTE: this is where the power-systems agent's Group-110 octet-string filler lives.] Fallback if no inert standalone pad frame passes DNP3/Zeek check.
- **γ — switch-tags + host/co-processor pads (hybrid).** Switch marks target bucket in a bridge/tag; a host/SmartNIC inline does insertion + seq translation with a real TCP stack (handles retransmit/SACK natively). Cost: leaves pure-in-network claim. Lowest-RISK for the seq-translation element. Honest analogue of the DCRN edge-bound recommendation.
Most promising: α for the DNP3 size range; α′ when coupling with DCRN / large buckets; γ = risk-minimizing escape hatch for TCP seq consistency under retransmit/SACK.
NEW vs standard: standard [L] = conditional-emit padding, dp68 recirc-hold+self-clock, CRC-16/DNP + IP/TCP Checksum() externs, per-tuple Hash. Genuinely NEW = (1) using DNP3-over-TCP self-delimiting framing to convert an impossible tail-append into a proven pad-BEFORE-residual; (2) the per-flow TCP sequence-space translator (seq+=Δ/ack-=Δ) as an explicit bounded non-proxy dataplane element with a runtime-Δ incremental checksum. Seq-translation-for-insertion exists in NAT-ALG literature but not posed as an in-network DNP3 size-defense element.

## 4. First compile-only probes
Compile on switch SDE 9.13.2 (cmake $SDE/p4studio && make && make install), gated-restart discipline (stop/mask gc-switchd first).
- **Probe A — geometry + constant checksum (proves K1, K3-constant, PHV of one pad header):** parse Eth/IP/TCP; on matched DNP3 response unconditionally setValid() ONE constant 10-B pad-frame header between tcp and residual; ip.total_len+=10; constant guarded IP+TCP checksum delta; forward. No bucketing/Δ/recirc. PASSES iff bf-p4c compiles clean (watch Class-6 silent ICE FIRST), resource report fits, captured frame is well-formed Eth|IP|TCP|padframe|response a DNP3 parser + Zeek accept.
- **Probe B — per-flow Δ translator (proves K3-variable + X3, the real risk):** add reg_flow_delta, seq+=Δ/ack-=Δ by direction, runtime-Δ incremental TCP-checksum fixup. PASSES iff the runtime guarded carry lowers to native ALU with no Class-6 ICE (MAKE-OR-BREAK), and a two-way DNP3 exchange shows the outstation issuing NO challenge-ACK/RST + master parsing the padded response, with idempotent re-padding on forced retransmit.
Bucketing, ladder, fail-open, DCRN coupling are additive once A+B pass.

## 5. Bottom line
Carousel not impossible, not the right tool. Deparser-order crux is real but sidestepped by DNP3-over-TCP framing (prepend a constant benign frame — GridCloak geometry). CRC/checksum machinery already runs on this chip in p4_decoy [L] and mostly dissolves for a constant frame. The one element that makes size harder than timing = **TCP sequence-space consistency under byte insertion** — a bounded per-flow non-proxy translator whose runtime-Δ checksum update is the top compile risk (Class 6) and whose retransmit/SACK behavior is the top rig risk. Build order: one-pass prepend ladder (α) → add Δ translator (X3) → bucket + fail-open → optionally fold into DCRN recirc (α′). First bf-p4c compile on 9.13.2 turns stage/PHV/Class-6 inferences into facts.
